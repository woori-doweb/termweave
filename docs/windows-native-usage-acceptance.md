# Windows 네이티브 사용자 관점 완료 판정 기준과 검증 계획

TermWeave Windows 네이티브 설치본을 **사용자가 실제로 쓸 때** 기능별로 정상 작동하는지, 쓰기 편한지, 멈춤·지연·과도한 리소스 점유가 없는지를 판정한다. 이 문서가 기준의 정본이고, 결과는 9절에 기록한다. CI·unit 통과는 이 문서의 판정을 대신하지 않는다.

## 1. 대상과 환경

| 항목 | 값 |
|---|---|
| 후보 | 브랜치 `windows-native`, 설치 시점의 `HEAD` (설치본 `source_sha` 와 같아야 함) |
| 설치본 | `install.ps1 --dir <새 경로>`, `127.0.0.1:7317`, herdr 0.9.5 헤드리스 서버 |
| 클라이언트 | Edge 앱 창(`msedge --app=http://127.0.0.1:7317`), 1400x900 창. 자동 측정은 별도 테스트 프로필 + CDP 로 같은 Edge 를 구동 |
| 측정 도구 | Playwright(`playwright-core`, 저장소 의존성) CDP 연결, PowerShell `Get-Process` CPU 시간 차분, 페이지 `PerformanceObserver(longtask)` |
| 증거 | `evidence/windows-native/usage-<run>/` (gitignore). 판정 요약만 9절에 남긴다 |

## 2. 판정 원칙

1. **사용자 관점:** 사용자가 보는 화면과 체감 시간으로 판정한다. 내부 로그만으로 통과시키지 않는다.
2. **측정값으로 판정:** 모든 기준은 수치 또는 관찰 가능한 화면 상태다. "될 것 같다"는 미판정이다.
3. **판정 값:** `통과` / `실패` / `해당 없음`(이 PC 에 외부 의존이 없어 기능 자체를 쓸 수 없음, 사유 필수) / `미판정`(측정 못 함, 사유 필수).
4. **해당 없는 기능도 사용자 경험은 판정한다:** 열었을 때 멈추지 않고, 왜 못 쓰는지 화면이 알려줘야 한다(F17).
5. **멈춤 정의:** 메인 스레드 long task 500 ms 이상, 또는 입력 후 2 s 안에 화면 반응 없음.
6. 기준을 측정 후에 바꾸지 않는다. 기준이 틀렸다고 판단되면 바꾼 이유와 함께 9절에 기록한다.

## 3. 공통 기준 (모든 기능에 적용)

| ID | 기준 | 측정 |
|---|---|---|
| C1 | 사용 중 처리되지 않은 페이지 예외 0건 | CDP `Runtime.exceptionThrown`, `pageerror` |
| C2 | 정상 동작 경로에서 API 5xx 0건 (외부 의존 미구성 기능의 의도된 오류 응답은 제외하고 별도 표기) | 응답 상태 수집 |
| C3 | 메인 스레드 long task ≥ 500 ms 0건, 200 ms 이상은 기능별로 기록 | `PerformanceObserver('longtask')` |
| C4 | 조작 버튼·아이콘은 접근 가능한 이름(aria-label/title/텍스트)을 가진다 | DOM 검사 |
| C5 | 대화상자는 Esc 또는 닫기 버튼으로 닫힌다 | 조작 |

## 4. 성능·리소스 기준

| ID | 기준 | 측정 방법 |
|---|---|---|
| P1 | 앱 창 열기 → "연결됨" 표시까지 3 s 이하 (3회 중 최대) | reload 후 상태 텍스트 대기 |
| P2 | 키 입력 → 터미널 화면 반영 지연: p50 ≤ 50 ms, p95 ≤ 150 ms, 최대 ≤ 500 ms (60자) | keydown 시각 → mirror 행 변화 시각 |
| P3 | 대량 출력(20,000줄): 화면에 마지막 줄이 출력 종료 후 3 s 안에 나타남, 출력 중 키 반영 p95 ≤ 1 s, long task ≥ 500 ms 0건 | 출력 중 입력 지연·long task 측정 |
| P4 | 유휴 60 s(창 표시, 조작 없음): TermWeave 서버 CPU ≤ 2 %(코어 1개 기준), Edge 렌더러 ≤ 5 %, herdr 는 기록(창 닫힘 대비 증가분) | CPU 시간 차분 |
| P5 | 창 최소화(hidden) 30 s 동안 HTTP 폴링 요청 0건 | 요청 수집 |
| P6 | 메모리: 서버 Private ≤ 400 MB, 반복 사용(대화상자 20회·대량 출력 1회) 전후 JS heap 증가 ≤ 30 MB(GC 후) | `Get-Process`, CDP `Performance.getMetrics` |
| P7 | 장시간 실행: 설치 후 수 시간 유지된 서버의 CPU 평균 ≤ 1 %, Private ≤ 400 MB, 핸들 수 비정상 증가 없음 | 실행 시간 대비 누적 CPU |
| P8 | `install.ps1` 시작 → health 정상 ≤ 40 s(빌드 포함 설치는 기록만), `--stop` ≤ 10 s, stop 후 소유 프로세스 0 | 명령 소요 시간 |

## 5. 기능별 완료 판정 기준

| ID | 기능 | 사용자 관점 완료 기준 | 사용성 기준 | 측정 |
|---|---|---|---|---|
| F1 | 설치·확인·중지 | `--check` 가 상태별로 0/1/2, herdr 꺼짐이면 원인과 다음 행동을 안내, `--stop` 후 프로세스 0 | 안내문만 읽고 다음 행동을 알 수 있다 | M10 run (`g006-off-1`, `g006-on-1`) 재사용 + P8 |
| F2 | 연결·상태 표시 | 창을 열면 "연결됨", herdr 가 꺼지면 연결 문제를 화면에 표시, 다시 켜면 새로고침 없이 회복 | 연결 상태가 상단에서 항상 보인다 | P1, herdr 중지·재시작 관찰 |
| F3 | 워크스페이스·패널 목록 | herdr 의 workspace/pane 과 사이드바가 일치, 선택하면 해당 터미널이 열린다 | 현재 선택이 눈에 띈다 | herdr `pane list` 대조 |
| F4 | 터미널 입력·출력 | 영문·한글·Enter·Ctrl+C·화살표·Tab·붙여넣기가 셸에 정확히 전달되고 화면과 `pane read` 가 같다 | 키바(Esc/Tab/Ctrl/방향) 가 동작 | P2, `pane read` 대조 |
| F5 | 대량 출력·흐름 제어 | 대량 출력 중에도 화면이 멈추지 않고 끝까지 표시, 이후 입력 정상 | 스크롤로 이전 출력 확인 가능 | P3 |
| F6 | 패널 추가·삭제·이름 변경 | UI 조작이 herdr 에 반영되고 화면이 2 s 안에 갱신, 삭제는 확인을 거친다 | 실수로 지우지 않게 확인 대화상자 | herdr 대조, 반영 시간 |
| F7 | 분할 보기 | 여러 패널을 동시에 보고 각 패널에 독립 입력 | 분할 경계·활성 패널이 구분된다 | 화면·입력 대조 |
| F8 | 에이전트 상태·Needs-you | herdr 상태(working/blocked/idle)가 2 s 안에 아이콘·배지·"응답 필요"에 반영 | 응답 필요 패널이 목록 상단에 모인다 | `report-agent` 후 반영 시간 |
| F9 | 채팅 보기 | 채팅 탭이 열리고 에이전트 없는 패널에서 멈추거나 빈 화면으로 남지 않는다 | 상태 안내가 있다 | 화면 관찰 |
| F10 | 검색·명령 팔레트 | 단축키/버튼으로 열리고 패널을 찾아 이동 | 결과가 즉시(≤ 300 ms) 갱신 | 조작·시간 |
| F11 | 파일 보기 | 패널 작업 폴더의 파일 목록·파일 내용이 열린다(Windows 경로) | 경로가 읽힌다, 닫힌다 | 조작 |
| F12 | 알림 | 알림 패널이 열리고 에이전트 상태 알림이 쌓인다, 비우기 동작 | 읽지 않은 수 표시 | 조작 |
| F13 | 설정·외관 | 설정 창이 열리고 변경(예: 글꼴 크기)이 즉시 적용·새로고침 후 유지 | 닫으면 원래 화면 | 조작 |
| F14 | 웹 미리보기 | 로컬 포트를 열면 미리보기가 표시된다 | 닫기 가능 | 로컬 HTTP 서버로 조작 |
| F15 | tmux | Windows 에서는 tmux 가 없다: 탭을 눌러도 멈추지 않고 사용 불가 사유를 표시 | 사유가 사용자 언어로 보인다 | 조작 |
| F16 | 화면 크기 적응 | 1366x768 과 390x844(폰 폭)에서 주요 조작이 잘리지 않는다 | 가로 스크롤 없음 | 스크린샷 검토 |
| F17 | 외부 의존 기능(음성, 휴대폰·푸시, 원격 PC, OpenRig, Android) | 패널이 열리고 멈추지 않으며, 미구성 상태를 설명한다. 실제 기능 동작은 `해당 없음` | 설정 방법 안내가 있다 | 열기·닫기·C1·C2 |
| F18 | 한글 IME (AC-U2), Needs-you 육안 (AC-B5) | 정본 9문장 9/9, 사용자 육안 확인 | — | 사용자 수행. 원문 미제공이면 `미판정` |

## 6. 실행 절차

1. 후보 커밋 후 새 `--dir` 에 설치(F1, P8), `environment` 결속 확인.
2. 테스트 프로필 Edge 를 CDP 로 띄워 Playwright 하네스로 F2~F17, C1~C5, P1~P6 을 측정한다.
3. 같은 시간대에 `Get-Process` 로 서버·런처·herdr·Edge 의 CPU 시간과 메모리를 샘플링한다(P4, P6).
4. 장시간 실행 중인 설치본이 있으면 누적 CPU·메모리로 P7 을 판정한다.
5. 실패 항목은 원인을 분류한다: 제품 결함 / herdr 측 / 환경. 제품 결함은 수정 후 해당 항목과 공통 기준을 다시 측정한다.
6. 끝나면 `install.ps1 --stop` 으로 정리하고 프로세스 0 을 확인한다.

## 7. 범위 밖

- 비목표(f-nongoals-v5): 네이티브 창, ConPTY 직접 소유, imeDiff, 플러그인, mirror 렌더 개선.
- 외부 서비스 계정·토큰이 필요한 실제 동작(음성 전사, 푸시 전달, Tailscale·Cloudflare 원격 접속).

## 8. 실패 시 처리

- 기준 미달은 숨기지 않고 `실패` 로 기록한다. 측정 조건(창 가림, 런너 부하)을 함께 적는다.
- 제품 결함은 원인 수정 + 해당 측정 재실행. 재실행 통과 전에는 `실패` 로 둔다.
- herdr 쪽 문제는 재현 조건과 수치를 남기고 TermWeave 판정과 분리한다.
